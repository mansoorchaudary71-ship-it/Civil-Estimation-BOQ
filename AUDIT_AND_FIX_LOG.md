## Pillar 1 lead — First-load blank white page (~20 s, needed a reload) — INVESTIGATED FROM CODE

**Report (parent, live check 2026-11-20 ~20:38 PKT):** on the home page, the FIRST load showed a blank white page and needed a reload plus ~20 seconds before the app rendered; after that it loaded fully.

**Mechanism established from code (reproduces the report):**
- `index.html`: `<div id="root" class="overflow-x-clip w-full"></div>` is **empty** — no loading placeholder, spinner, skeleton, or text. `body` is `bg-white` (light) / `dark:bg-[#1F1D1A]`. Before JS loads and React mounts, the page is literally a blank white screen. Any delay in JS loading/parsing = blank white screen for that long.
- `src/main.tsx`: imports `App` statically; no `lazy`, no `Suspense`, no dynamic `import()`.
- `src/App.tsx`: **no** `lazy` / `Suspense` / dynamic `import()` anywhere (grep: zero hits). The ENTIRE app (all 75 tools, all engines, all components) is bundled into ONE chunk.
- `vite.config.ts`: **no** `build.rollupOptions.output.manualChunks`, no code splitting of any kind. `base: "./"`.
- **Bundle size (fresh build in the working copy, 2026-11-20, pillar 1):** `dist/assets/index-CO6xv8C8.js` = **7,139.53 kB** (gzip 1,861.79 kB; on disk 7,148,921 bytes) — larger than the earlier 6,948.53 kB build; the bundle grew ~200 kB since. Vite warns "Some chunks are larger than 500 kB" (this chunk is ~14× the threshold). Build passes in 1m 53s.
- So: a first-time visitor downloads ~1.86 MB gzipped JS (more uncompressed to parse) before ANYTHING renders, with a blank white page the whole time. On a slow/mobile connection that is ~20 s. After the first successful load the JS is cached, so subsequent loads are fast — consistent with the report ("after that it loaded fully"). The "needed a reload" part is consistent with the first load timing out or stalling (e.g. the Google Fonts stylesheet request below) and the cached second load succeeding.
- **CORRECTION (pillar 1, verified):** the font preload is **NOT** a live defect. `index.html:50` has `<link rel="preload" href="/fonts/MonaSans.woff2" ...>` (absolute path, as first noted), but Vite rewrites it in the built output — `dist/index.html` contains `./fonts/MonaSans.woff2` and `dist/fonts/MonaSans.woff2` exists (100,780 bytes). Same rewrite applies to the `@font-face` in `src/styles/mona-sans.css`. The source should still be changed to a relative path so behaviour does not depend on Vite's rewrite, but this is not a cause of the blank first load. The real remaining render-blocking external request is the Google Fonts Inter stylesheet (`index.html:51-54`, present verbatim in `dist/index.html`) — the site already self-hosts its primary face (Mona Sans) and Inter is only a fallback for non-Latin glyphs per the `mona-sans.css` comment, yet the full 5-weight family is fetched render-blocking on every load.
- **Build also bundles a server nobody serves:** `package.json` `build` = `vite build && esbuild server.ts --bundle ... --outfile=dist/server.cjs` — the `dist/server.cjs` is dead weight in the Pages artifact (static hosting serves no Node server). Minor; it wastes build time, not load time.
- **Severity:** HIGH (frontend pillar) — affects every first-time visitor; the site looks broken for ~20 s on first load.
- **Suggested fix (Phase 2):** (1) add an inline loading placeholder inside `#root` in `index.html` (a small inline-CSS spinner/skeleton with the brand mark — renders on first paint, replaced by React on mount); (2) code-split with `React.lazy` + `Suspense` per tool route (or at least per tool group) so the home page loads a small initial chunk; (3) add `manualChunks` for vendor code (react, react-router, recharts, jspdf, html2pdf); (4) drop the Google Fonts Inter link (self-host Inter weights like Mona Sans, or fall back to system fonts for non-Latin glyphs); the font preload path itself is fine in `dist` (see correction above) but should still be made relative in source. Verify by rebuilding and checking the initial chunk size + a cold-load render.
- **Status: CONFIRMED by pillar 1 (COMPLETE 2026-11-20 ~20:58 PKT; full report `~/workspace/cep-fix/audit-2026-11-20/pillar-1-frontend.md`).** Fresh build verified the 7.14 MB single chunk; the lead is reproduced. Full pillar-1 findings are folded into the Pillars section below.
